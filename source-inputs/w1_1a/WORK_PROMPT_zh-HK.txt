C. 先修正兩個具體美術問題

C1. 曲面 normals

目前 src/art/geometry.ts 的 sphere 把球面方向向量直接當成非等比 ellipsoid 的 normals；cylinder 側面 normals 使用 (cos(a), 0, sin(a))，沒有反映橢圓截面與錐度。這是來源可確認的幾何問題；在畫面中的影響程度尚未實際驗證。

請正確處理非等比縮放、錐度與旋轉後的法線，正規化並檢查三角形朝向。同步檢視相關 torus／其他縮放形狀；只修有具體問題的部分。
為橢球與錐形／橢圓柱做少量有意義的數學回歸檢查，例如 normals 與局部切線近乎垂直、長度有效、無 NaN、朝向正確。重新產出受影響 GLB，再做結構驗證及獨立重載。
GLB validator 無錯誤不等於實際光照已正確。

C2. Reduce Motion 顧客站位

目前兩位顧客只有在 !prefers-reduced-motion 時才於迴圈設定位置。若從啟動就開啟 reduced motion，營業時可能同時顯示於原點。

為每位顧客先設置不同、合理、不穿家具的靜態位置與朝向。將「是否出現」「靜態站位」「是否播放動作」分開處理。
測試：初次載入已開 reduced motion、運行中切換、Low、開／關店、模式切換。停用動態後仍保留有意義的構圖與必要選中提示。

D. 美術精修

D1. 構圖及光影

遵守 KeEv Living Diorama：真正 3D、35–45° curated 2.5D 視角、有限縮放及旋轉。

以一個清楚的主要商品區作視線焦點，建立窗邊／商品區／後牆的前中後層次。保留玩家看清店員、貨架、收銀區及可操作區的視線。
桌面閒置視圖以世界約佔 70–80% 為方向；手機開啟面板時以可操作、可讀及可關閉為先，不為比例硬縮字體。
檢查正常畫面、Zen、面板開啟、窄畫面及容許的鏡頭角度，修正遮擋與不必要空白。

奶油牆、自然暖木、鼠尾草綠為主；淡紫作選中／品牌小面積點綴。
暖窗光有清楚方向，窗外或窗邊可有稍冷的環境色；受光面保留細節，陰影仍看得清商品。先調現有燈與陰影，不靠整幅畫面泛白來表達溫柔。
先改善接地感、窗框影、家具底部與貨架層次，控制 shadow acne、漂浮感與過硬陰影。
本輪只處理目前靜態光照場景，不把可選美術預覽誤接為真實東京時鐘／天氣系統。

D2. 材質

現有所有 PBR 材質主要按顏色＋透明度共用，roughness 為 0.88。請引入少量語義清楚的材質角色，讓木、紙、布、陶瓷、玻璃與小面積金屬有可辨別的反應。

- 木：暖而啞，微弱紋理或色階差異，邊緣乾淨。
- 紙：柔白、不刺眼，可看出書頁厚度。
- 布：啞面、柔軟，有少量摺線或織物提示。
- 陶瓷：小範圍柔和高光，保留杯形與把手。
- 玻璃：透明度與輪廓可讀，避免為追反射大幅增加成本。
- 角色皮膚／頭髮：與環境材質分工，朝柔和 anime-toon 及簡潔陰影發展。

材質 batching、runtime 與 GLB export 要使用一致的材質身份，不能把同色而不同材質的物件誤合併。
若新增貼圖或 shader，保留來源、參數、UV／烘焙資料與授權；重要外觀應有可供原生端重建的清楚描述。小型可重用材質組即可，不建立不必要的大型素材管線。

D3. 商品與佈置

優先精修筆記簿、鉛筆、陶杯、布袋四件可近看主商品：
- 正常遊戲鏡頭下仍能辨認，不需要每次拉近。
- 杯口、把手、書脊、紙頁、筆尖、袋帶及縫線具有合理厚度與比例。
- 以小幅、受控的擺放角度／高低建立自然陳列，保留空間。
- 十款商品的縮圖、色彩、模型與 Offering ID 對應一致。

生活感可來自已有包裝區、價牌、植物與書紙細節。裝飾有用途、有留白；不能遮擋售價、架號或可點選範圍。
現有茶罐、空杯、曲奇盒不會因為「療癒」而自動冒熱氣；熱氣應留給日後有相應內容設定的熱食／熱飲。

D4. 通用角色與動作

保留約 3.5–4 頭身；優先提升臉部方向、眼睛、髮型輪廓、圍裙與自然站姿的可讀性。角色仍是 generic，不擅自命名或代替正式角色。

現有顧客循 sin/cos 路線移動；改成少量合理停留點、望商品、短暫停留及自然轉向，避免持續兜圈、穿過陳列架或整個身體像浮標上下飄。
若本輪用分件 pivot 做點頭／呼吸／手部小動作，要保留語義清楚的層級及作者資料。不要宣稱靜態 GLB 已成為完成的骨架動畫管線。
若沒有可信的步態，採用合理靜態瀏覽與局部動作，將正式行走動畫列入角色管線後續；不要用滑行掩飾未完成步態。

動作屬 presentation，絕不產生交易或改變經營時間。

E. UI 精修

保留目前清楚的「店名＋現金」層級與五個主要導航，以及已修正的草稿、焦點、scroll、selected shelf 同步。

- 為店務、入貨、報告、手帳、更多建立一致的原創小圖示；取代筆畫及基線不一致的文字符號。保留文字標籤。
- 圓角、描邊、陰影與留白一致。淡色面板上的文字、價格、缺貨、錯誤及 focus 必須可讀。
- 商品縮圖增加乾淨輪廓與有意義的材質提示，保留真實庫存及成本資訊。
- 面板開合、按下、選中可用短而柔和的過渡；約 150–220 ms 是起始調整範圍，不是 Bible 硬規格。
- 操作立即生效，動畫不延遲輸入、結算或解除 busy。
- 保留五種語言、觸控目標與鍵盤操作。測試 320／375／430 CSS 寬度以及桌面；不把 iframe 測試稱為實體手機驗收。
- 真正的錯誤提示需清楚，日常經營訊息則安靜、不反覆搶焦點。

F. 本輪特效：三組事件回饋＋最多一組環境效果

F1. 選中／上架

選中貨架時，淡紫底框短暫柔和淡入，其後維持穩定。成功上架可加一次很輕的落定／亮度回饋；模型最終停在真實位置。
避免一直閃爍、一直呼吸發光或讓所有商品彈跳。
Reduce Motion／Minimal FX 使用穩定框線與即時狀態變化。

F2. 真實成交／補貨

沿用已提交的 snapshot／eventSequence 差異，顯示一次短而清楚的文字或商品回饋。
成交、補貨、恢復支援、樣本揭示的視覺語意要分開；恢復支援不是銷售或利潤。
離線累計與同一次多筆成交合併；reload、focus、tab 切換、重複 command 不重播過去成交。
不為每個裝飾客人憑空生成銷售；不逐枚噴出金幣，不使用假收入數字。
保留必要文字／無障礙狀態訊息，不依賴動畫理解結果。

F3. 現有樣本揭示

為目前 discovery.graybox-sample 做一次短、柔和、可跳過的展示：包裹局部光感／揭示動作＋商品卡＋清楚完成狀態。
可在不影響操作的前提下短暫聚焦；不能鎖住玩家強迫看完整演出。
維持目前 Select 品質、獨立 Unique tag、0 stats，以及原解鎖／領取規則。這不是 Prestige 雨夜玻璃小燈，也不是 Masterpiece 演出。
先確認權威狀態已提交，再播放呈現；跳過動畫、關閉視窗或 reload 不影響獎勵狀態，也不重複給予獎勵。
處理現有 parcel 在 revealed=true 立即隱藏的生命週期：可用獨立 presentation proxy 完成短暫過渡，不反轉或延遲核心 reveal commit。
若使用局部 Glow，僅包含明確物件、低強度並可降級；不要預設整個場景都發光。

F4. 最多一組環境效果

優先候選：只在窗邊受光範圍出現的極少量、低對比、緩慢塵粒，服務空間深度。
設定粒子數量、發射率、透明面積與生命週期上限；初始值要保守，實際畫面確認後再調。
先完成靜態窗光與陰影；若效果需要額外光束形狀，保持局部、淡薄且與窗洞一致，列入同一效果預算。
如果實際畫面看起來像灰塵太多、煙霧、泛白或干擾商品，就減弱或關閉。
Low／Minimal FX／Reduce Motion 可完全關掉這組環境效果，保留清楚的世界與必要操作回饋。
本輪不疊加全屏 Bloom、DoF、多層雨雪、動態反射或其他持續後製。樹影／植物微動可作替代方案，不與窗邊塵粒一起擴展成一大組環境系統。

F5. 共用生命週期與聲音

效果採單一 presentation 更新來源，使用合理 delta time 並限制大時間跳躍。隱藏分頁時暫停裝飾效果；回到頁面不追播積欠粒子或整段動畫。
尊重系統 Reduce Motion；提供簡單 Minimal FX 選項，保存於 presentation preferences，不能改動經濟 schema 或存檔分區。
物件池／重用、dispose、取消訂閱及場景重建要完整，不能隨成交無限增加 mesh、listener、timer 或 GPU 資源。
同時突出一個重要回饋；必要時合併日常通知，避免聲畫密集重疊。
音訊維持 opt-in。只調整現有成交音的柔和度、音量與節奏；如有需要最多補一個來源清楚的輕柔揭示 cue。新素材需權利清楚。
完整城市 BGM、adaptive layers、正式 voice production 留在後續音訊工作。

G. 效能、移植與既有成果

現有 Babylon.js 8.32.0、TypeScript、Web 管線可繼續使用；不因這輪美術任務全面升級引擎或換 framework。

沿用 High／Low／Auto；在現有 adaptive decision 內讓新效果正確降級。優先減少環境粒子、額外 glow／反射或裝飾成本，維持商品辨識、角色輪廓與操作清楚。
新增效果要有明確資源預算，記錄 mesh／material／draw call（若工具可量測）、材質／貼圖／粒子與下載量的前後差異。未量到的項目寫未量到。
30／60 FPS 是 Bible 的後續裝置目標；沒有真實裝置及有效量測，不宣稱已達標。可用環境支援渲染時，記錄 viewport、DPR、品質、場景與可見分頁的 frame-time 樣本；不要把 build 時間、NullEngine 或平均估算冒充實際 FPS 通過。

保留：
- normal／sandbox 原存檔鍵、schema 2、遷移、CAS、去重、免費重開支援及所有 W1.1 修正。
- 商品／角色／道具／材質的穩定 ID。
- 純幾何／作者來源、GLB masters、Web 衍生資源、原始音訊與圖示、授權及來源。
- 新 VFX 的中立設定：id、觸發條件、持續時間、顏色、強度、數量上限、降級及 reduced-motion 行為。
- 若新增動畫，保留關鍵幀或動作參數、節點／骨架定義與匯出版本。

區分可重用素材／設計與平台實作。GLB、貼圖、音訊、圖示和配置可以作為 Android／iOS 後續資源；Babylon shader、粒子控制、HTML/CSS、input 及 native renderer 仍需適配與實測。不要承諾特效程式或 Web 場景直接零修改成為 Unity／原生版本。

用隔離的美術 review fixture，保護使用者目前 normal 及 sandbox 進度；不要覆寫既有 sandbox 只為擺拍。

在相同 viewport、相機、zoom、品質、fixture 下比較前後：
1. Zen 全店。
2. 正常遊戲＋選中架 2＋打開入貨／店務面板。
3. 四件主商品與通用店員近景。
4. 窄視窗可操作畫面。
若本輪改動畫／VFX，再看實際短片或實際動態；靜態截圖不能代表流暢度。

按實際畫面修正：
- 主商品可辨、材質有差別、光影保留細節。
- 沒有明顯穿模、浮空、法線反常或 reduced-motion 角色重疊。

- 微動低調，選中清楚，事件回饋只播放一次，Minimal FX 仍能理解結果。

H2. 環境仍不能渲染時

在既有授權範圍內更新同一 Site 的美術候選，保留可回退的版本紀錄；不要改存取政策。
