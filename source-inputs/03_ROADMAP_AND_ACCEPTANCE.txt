Final Tokyo Slice gate
Use all eight original gates: Gameplay, Economy, Retention Fantasy, Character, Discovery, Visual, Performance and Content Pipeline. 2. W0/W1 EVIDENCE CHECKLIST

A. Source and scope
• Full Bible read and original hashes retained.
• Technical extension identified; frozen design untouched.
• Provisional fixtures and future content distinguished.
• No unsupported claim that native source already exists or native gates passed.

B. Core and economy
• Use an explicit expected-result fixture covering a purchase, sale, cost breakdown and final inventory/balance.
• Reject invalid quantities and actions; no negative stock, duplicate command payout or double-expensed purchases.
• Verify applicable modifier aggregation/cap/order rules.
• Fixed snapshot + WorldState + logical interval/event/random state gives the same result on repeated replay.
• Verify cross-runtime parity for the C# path when available. If the fallback is used, document its actual scope and code-to-port status.
• Verify numeric bounds, rounding and lossless serialization on any boundary used.
• Compare at least two render settings/update schedules and a background/resume scenario while keeping economic inputs constant.

C. Save/time
• Reload preserves inventory, finances, layout and implemented tutorial/discovery/set state.
• Already-settled elapsed time cannot pay out twice, including after a reload.
• Economic state and settlement watermark commit atomically; a crash cannot persist just one. Guard against concurrent stale-tab overwrites.
• One 60-minute settlement equals two consecutive 30-minute settlements under identical commands/event inputs, with explicit rounding/fractional remainder carry.
• Interrupted/invalid save data produces a recoverable error; current good data is not silently destroyed.
• Define a minimal supported version/migration fixture and reject unsupported newer versions safely.
• Test mode and normal mode use separate namespaces and are labelled clearly.
• Record rollback/long-gap policy; do not invent final balance caps.
• Keep online/server-authoritative and production-save migration claims pending.

D. Assets
• At least one shop fixture plus a generic skinned interchange fixture (at least two bones, normalized weights and a named skeletal clip) is exported and reloaded from its files.
• Preserve generator/authoring source, textures and required companion files.
• Validate glTF/GLB and inspect orientation, pivots, materials and named animation in the available viewer.
• Record source rights/provenance without inventing a licence.
• Native status remains not tested unless actual Unity evidence exists.
• Web optimization leaves the source master intact.

E. Browser/user experience
• Actual browser opens the hosted or local development build available to the cloud worker.
• A user can complete a real stock/display/sale/report decision sequence.
• Verify loading/error messages, input, panel readability, resize and narrow/touch layout.
• Check console/network failures, persistence after refresh and background/resume.
• Record browser/version/viewport and GPU/acceleration mode if known.
• Measure actual payload/loading/frame behaviour without presenting cloud hardware as a phone benchmark.
• Only save screenshots as user-facing deliverables when appropriate/authorized; routine visual checks can remain internal with a text evidence summary.

F. Rebuild and handoff
• Source archive/checkpoint contains actual code, content, assets, licences, lockfiles and commands.
• A current handoff identifies what's done, partial, provisional and blocked.
• Cleanup preserves anything needed for future shared use or rebuilding.
• No tokens/keys/session files in the distributable source archive.

3. STATUS VOCABULARY

Report each gate as PASS / PARTIAL / BLOCKED / NOT TESTED with a short evidence reference. Do not turn NOT TESTED into PASS because the technology is theoretically compatible.

Maintain separate asset fields for:
• approval_status: placeholder / provisional / approved;
• source_retained: actual path and hash;
• web_validation: not_tested / passed / failed;
• unity_import: not_tested / passed / failed;
• android_validation and ios_validation: not_tested / passed / failed;
• portability_class: shared_data / shared_source_candidate / interchange_asset / platform_adapter / temporary;
• known_adaptation: concrete material/controller/UI/import work still needed.
