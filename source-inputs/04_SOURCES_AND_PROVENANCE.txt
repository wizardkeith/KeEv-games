Supports browser-native 3D rendering and its scene/animation/material capabilities. It does not certify the game's art quality or device performance.

https://doc.babylonjs.com/features/featuresDeepDive/Exporters/glTFExporter

5. Unity glTFast — Editor Import (6.20 documentation consulted)

Documents importing .gltf/.glb into Unity asset components/prefabs. Record the actual selected Unity/importer version during the later native gate rather than treating this reference version as a tested project dependency.

https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.20/manual/features.html
Documents feature limits and animation/material integration caveats. The first sample's conservative four-influence skinning requirement is an engineering choice based on this documented import subset.

7. Microsoft — .NET WebAssembly Browser App / JS interop
https://learn.microsoft.com/en-us/aspnet/core/client-side/dotnet-interop/wasm-browser-app?view=aspnetcore-10.0
Documents running .NET libraries from JavaScript without requiring Blazor. Does not prove that the next Work cloud environment has the SDK/workload or that this game's integration/startup budget will pass.

8. Unity — API compatibility levels for .NET
https://docs.unity3d.com/6000.0/Documentation/Manual/dotnet-profile-support.html
Supports the .NET Standard compatibility boundary and explains limits for other assemblies/AOT. A modern host-only WebAssembly adapter is not the same as the portable shared library.

9. MDN — Page Visibility API
https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API
Documents background rendering/timer restrictions. Hence elapsed-time simulation and background/resume must be explicit.

Explains browser storage lifecycle. Prototype persistence is not equivalent to a permanent cloud account save.
