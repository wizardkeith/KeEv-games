C. 顧客：完整而有界的進出與瀏覽

C1. 同時最多兩位普通顧客；Low 至少保留一位。使用可重用 actor pool。
基本流程：
入口外／門檻 → 進店 → 沿通道到貨架 → 停看／轉頭／伸手查看 → 另一停點或離店。

普通瀏覽訪客可空手離開；不因此增加銷售、訪客統計或新需求。

對這個房間使用人工安排的 waypoints、貨架觀看點、櫃檯停點與簡單位置預約即可。
依現有桌子、櫃檯、牆與門的實際 footprint，加上角色半徑檢查通道。
兩位客人避免相穿；同一停點已佔用時，另一位選其他站點或在安全處稍等。
不需要引入完整 navmesh、物理或群眾模擬。

C3. 入口必須真的可通行
現有門框／玻璃後仍有後牆的部分，要修成合理門洞與可開合門葉，或使用實際可通行的適當入口。
角色跨門檻要可見。不要從房間中心出現、穿過實牆、在展示架旁突然現身。
門的動作跟進出協調，門葉不能掃過站立角色。

C4. 真正踏步
先為需要行走的角色補足左右腿／腳樞軸或合適 rig。依 B4–B10 更新造型，保留 Bible 比例及角色身份。
步態相位依行走距離推進，配合速度／步幅；左右腳交替、輕微抬腳、落地，手臂輕擺。
起停與轉向要有過渡，站定時腳接地。不要以 root 平移、整個人搖擺或雙腳拖地取代行走。
可使用簡單 rigid-part animation；不必引入重型 skeletal 系統，但必須交出可讀步態。

C5. 建議節奏，按實機觀感調整
每個展示點停留約 4–8 秒；一次瀏覽／進出約 20–40 秒；入店時間錯開。
這些是起始調校值，可按房間尺寸及角色步幅合理調整，不是經濟 clock。

C6. 開店與關店
開店後顧客由入口錯開進來。
關店立即依原 core 停止營業；呈現層停止新入店，現有顧客沿路離開，未成交者空手離開。
不可等離店動畫結束才關店，也不可關店後因演出追加成交。
快速關店／重開要有連貫、有限的狀態轉換，不複製角色、不重播舊交易。

迎客：抬頭、輕揮手／點頭。
入貨：接過小箱、查看／點貨。
成交：轉身面向服務位置、拿袋／包裝、交收、點頭或微笑。
小工作可為交易讓位，之後自然回到 idle；開關 UI 面板或一般 repaint 不可不停把她重設 neutral。

D3. 空間與手部
保留 v9 已修正的 greeting 向外揮手，不重現手掌／拇指穿胸口。
新工作、拿袋、交收動作檢查手臂與衣服、櫃檯、道具的相交。
如安排 Misaki 走到貨架補貨，必須有可行路線和完整去回流程；不可伸長手跨店、滑穿櫃檯。
本輪優先完成櫃檯小工作、接貨點貨、成交交收與顧客步行。不要因要支援所有跨店補貨路線而延遲整輪交付。

E. 成交、入貨與陳列動畫：全部接駁真實已提交結果

E1. 只在成功 persistence commit 後觸發
沿用 Saves.command／Saves.settle 等既有成功 persistence commit → committed presentation 的邊界，涵蓋 Normal 自動結算及既有 Sandbox advance，不只接玩家點擊命令。
動畫不呼叫 settle／Saves.command，不獎勵現金、不扣庫存、不新增收入或成本。
已提交結果立即按既有規則顯示；不要等顧客行完或動畫完成才入帳。
動畫取消、隱藏、略過或品質降低，不可反向取消經濟結果。

E2. 正確認識 eventSequence
現有 src/core/simulation.ts 的 eventSequence delta 代表售出「件數」，不是交易筆數或客人人數。
src/presentation/feedback.ts 的資料只有 aggregate committed before/after；沒有可信的買家身份、單次購物籃或逐 SKU 成交事件。
因此：
- 可以挑選一位合適的現有 visual customer，演繹這次已提交銷售摘要。
- 道具使用 generic 紙袋／包裝；沒有來源資料就不指定袋內 SKU。
- 不建立「某 named customer 買了某件商品」的紀錄。
- 不因 sold=5 就生出五位客人或播五次交易。
- 不把演出角色數當真實客流／業績統計。

E3. 成交演出
真實 sold > 0 後，立即給可讀的收據／銷售回應；Misaki 在約 2.5–3 秒的主要手部演出內包裝或交袋。
如已有合理位置的客人，客人面向櫃檯、接袋／點頭，再沿既有通道離店。
如客人需要走過來，可以沿合理路徑移動；不要為了湊一次交收而瞬移。
如沒有合適客人，可用 Misaki 的包裝／收據回應該筆已提交摘要，顧客活動繼續。
主要手部演出時長不包括必要的行路時間；要讓玩家能看懂，但不要阻塞操作。

E4. 批量與同時事件
一次 settle／沙盒 advance 可能結算多件商品，只做一段代表性銷售演出，數字摘要使用已確認結果。
使用有限 active sequence 及最多一個有界 pending summary，或選擇有界合併／略過策略；明確實作及測試。
不得無限排隊、逐件補播、為了看完動畫推遲下一次正常 command。
新一輪動作不要讓舊 callback 取消新的動作。

E5. 成功入貨
出現小紙箱／貨袋、Misaki 接收與點貨，約 1.5–2.5 秒。
Saves.command 在套用玩家命令前會先 settle，因此同一個 buy commit 可同時包含賣貨與入貨。
不能用 inventory 的淨增加量當成實際送到的入貨量。
在命令送出時保存 item／quantity／target 的呈現上下文，僅在確認該命令成功套用後使用；若受限／拒絕／中止，不演成功入貨。
需要顯示數量時，使用確實已接受的數量或合法的 committed 結果；資料不足就不顯示推測數字。

E6. 成功上架／換陳列
對實際成功改動的架位做清楚的放下／整理／短暫柔和 highlight。
目標必須是該次命令原本捕捉且成功套用的架位，不是 await 後玩家目前選中的架位。
商品 mesh 最終仍取 authoritative snapshot；不要用裝飾道具額外改庫存或把不存在的商品放進真實陳列資料。
無變更的操作不假裝上架成功。

E7. 一個 commit 包含多種變化
現有 projector 只挑一個優先 kind；不可讓 sale 永遠吞掉玩家剛完成的入貨／上架回應。
保留兩項真實結果的清楚 UI 回應；3D 可按有界優先序串接或整合短演出。
必要時擴充 presentation payload 與 command context，但不要捏造 core 沒提供的交易明細。

E8. 去重與生命週期
保留 revision／epoch 去重、stale CAS、busy lock、transaction abort、不重播 baseline／reload／retry／import／mode-switch／離線結算舊動畫。
已成功 commit 的 delta，仍需按現有方式消耗及記錄，即使當時 hidden 或 epoch 已失效，避免返回時重播。
相機移動、UI redraw、一般 render 不可再創建銷售／入貨動畫。

F. 環境動態與特效

F1. 與更新後人物及店景整合少量生活效果
- 窗旁植物葉片緩慢微擺，花盆／根部穩定。
- 入口門葉及小門牌跟隨進出輕動。
- 窗邊合理受光區域少量光塵，使用有限物件池。
- 上架短暫 settle／柔光；成交用紙袋、收據及角色反應。
如有熱飲內容，蒸氣只出現在確實合理的熱飲道具；不要在袋裝茶、空杯或所有商品上加蒸氣。

F2. 藝術節制
人物、門、植物與光塵的節奏要有層次。
避免滿屏閃光、爆炸星星、大量金幣、鏡頭震動或不停跳動的物件。
不以增加 bloom、粒子數或相機動作替代人物行為。
同一場景關掉裝飾特效後，仍能辨認「有人逛店、有人工作」。

F3. 音效
可在既有玩家開啟的提示音設定下，配合輕門鈴、紙袋／紙箱或收據聲，避免重複密集播放。
保留靜音選擇。音效不是本輪視覺動態驗收的替代，也不是完成角色動作的前置條件。

G. 畫質、Minimal FX、Reduce Motion 必須拆開

G1. High／正常品質
最多兩位顧客；完整簡單步態；Misaki idle、小工作、成交／入貨動作；少量裝飾效果。

G2. Low
至少一位顧客仍會步行和看貨，Misaki 仍有清楚基本工作／成交動作。
先移除光塵、次要裝飾、昂貴陰影／反射，再按需要降低 pose 更新頻率；保持畫面和輸入順暢。
不要把人物凍結當成 Low 的主要實作。
可用固定較低頻率更新 pose 並合理插值；具體數值依實測決定。

G3. Minimal FX
關閉粒子、發光、非必要裝飾位移，保留基本人物步行與交易回應。
更新設定標籤／說明，清楚表達新行為。所有現有五語文案一起更新；不只改 zh-HK。

G4. Reduce Motion
獨立尊重系統偏好及已有應用內選擇。對此模式可減少／停止連續行走與 idle，用穩定姿態及清楚的文字／狀態回應。
無障礙偏好優先；不可為了讓影片看起來活潑而忽略。
若需要新增開關，保持簡單、可理解，並沿用既有裝置偏好保存方式。

G5. Auto
沿用或合理調整現有 Auto，但自動降 Low 後仍要有基本生命力。
不必在本輪重做完整自適應系統。如新增恢復機制，加入穩定門檻避免品質反覆跳動。
UI 顯示「Auto」不等於證明實際使用 High／Low；QA 記錄要分清設定值和有效層級。

G6. 分開動作通道
至少概念上分開 ambient／locomotion、staff/service sequence、decorative transient FX。
一個新收據或 UI 更新不可取消所有人物活動。
hidden／disposed／WebGL loss／import／mode epoch 仍要安全停止、清理或重建，不產生追趕播放。
切回頁面時直接回到合理當前狀態；不補播離開期間的進出、紙箱、成交或粒子。
品質切換要妥善完成或收束當前動作，不能留下半穿櫃檯的人、懸空購物袋或失去 owner 的道具。

H. 為 Android／iOS 後續保留可重用結構

H1. 角色資產
對需要改動的角色建立版本化分件／rig contract。
保留角色與經濟身份的現有綁定（v9 的 Misaki 使用 staff.graybox）；視覺資產改善不改寫角色的經濟能力。
保留 body／head／左右手臂等既有語意 ID；增加腿／腳等穩定 node 名稱、局部 pivot、rest pose、metres 與座標方向說明。
需要行走的角色一定有可用下肢動畫結構。Misaki 如維持櫃檯工作，可按實際動作需要調整，不必為未做的遠距補貨加入整套多餘系統。

H2. 動作資料
idle、walk、inspect、tidy、receive-stock、pack／handover、greet 等有穩定 clip ID 或等價的 engine-neutral 動作定義。
記錄 duration、loop、blend、foot-contact／handover 等必要標記。
將 presentation state／動作資料與 Babylon-specific 播放適配分開，避免未來只能照抄一大段 renderer code。
行走路徑與步態分層；原地 greeting 的零 root-motion 規則仍可保留，world locomotion 另行控制。

H3. 重新輸出實際受影響的資產
更新 authoring source、可重建方法、GLB／其他 master、manifest、hash 及版本。
若 GLB 包含 clips，檢查真正輸出的 clips、node hierarchy 與 runtime 行為一致。
若使用 rigid-part 程序動作，要如實交付 node hierarchy + 動作資料／adapter，不把它描述成已完成 skeletal clips。
現有兩個 static calm／smile GLB 不能當成新動作已可移植的證明。
本輪只承諾可重用資產及清楚接口；不宣稱已完成 Unity、URP、Android 或 iOS 的實機驗證。

H4. 新材質／貼圖／shader 的可重用資料
若使用 atlas，交 source、UV、texture/material references；GLB 要包含對應 TEXCOORD 及正確 image/sampler/material 引用。
若採 soft-toon shader，記錄跨引擎材質意圖及合理的標準材質 fallback；Babylon shader 不能宣稱可直接等同 Unity/URP shader。
不必為本輪先完成所有原生 adapter，但要誠實說明哪些可直接重用、哪些日後需重接。

分清楚角色路徑、步態、手部動作及表情。走路由實際移動距離驅動，並處理起停；手部演出依所需時間取樣。
不要把整個人上下搖、root 平移或固定位置小轉頭當作完整顧客活動。
分開 ambient／locomotion、service、decorative channels，避免新提示或 repaint 停掉所有人。
售出多件只做一段代表性演出；回饋來自真實成功 commit，遵守 E 節。

K4. 原生門、植物及窗外
門葉有正確 hinge／轉軸及實際門洞；跟進出相配，角色不穿實牆／門板。
盆栽根部和盆固定，葉片或葉簇在各自 attachment／局部轉軸附近小幅擺動；不同植物相位錯開。
如需要改善窗外，建立少量可見的枝葉、樹幹／枝條及遠景建築大形，僅服務現有窗景及 curated camera。
窗框、牆體及前後遮擋仍是真正 3D；檢查既有相機範圍不露出不合理邊界或吃掉選架操作。
不擴展成可遊歷城市、新地圖或完整天氣系統。日夜／天氣以現有 Bible 範圍及已實作狀態為準，不提前加入後續章節內容。
葉動、門牌、光塵使用克制節奏；店景漂亮來自形狀、材質、光影及構圖一起配合。

K5. 原生物件／特效
紙箱、紙袋、收據和陳列物件是場景內實際可管理的視覺道具，使用有限物件池或有界生命週期。
手持道具跟隨 hand socket；交接時正確切換 owner／parent，取消或 epoch 切換能安全收回，不留懸空袋。
使用少量粒子、材質參數或簡單動畫曲線完成適當光塵、輕柔提示與合理蒸氣；不堆滿畫面。
對同一材質 instance／shared material 的變更應檢查影響範圍，避免選中一件商品令全店同時閃。
UI 動態保持快速可操作，不在交易或存檔前等待動畫完成。

K6. UI 人像的範圍
先完成世界內的真正 3D 人物。故事／手記人像不是本輪前置功能。
若現有版面適合，可用一致原創靜態人像，或在性能可接受下使用新模型的畫面；任何額外動態人像皆需符合手機版空間及 Reduce Motion。
不為了展示素材增加大型彈窗、強制新劇情步驟或遮住開店 CTA／報表。
人物造型完成度以實際店內畫面判斷，不以 UI 頭像代替。

K7. 降級及有效設定
Low 優先減少粒子、影子、反射、遠景枝葉數及次要更新頻率；至少一位顧客仍行路，Misaki 仍工作。
Minimal FX 關閉裝飾效果，保留原生行路及必要工作／交易演出。
Reduce Motion 使用穩定姿勢及即時可讀狀態回應；不得為表現活潑而違反無障礙偏好。
現有 world.minimal(...) 由每次 draw 重覆呼叫；新 setter 要冪等，重覆套同一值不可取消／重啟正在做的原生動作。
quality／Auto 層級切換亦不可再一律呼叫「停止所有人物」；安全收束已移除 actor／道具，保留仍有效活動。

L4. 「revision 有增加」並不足以證明命令生效
v9 Saves.write 在持久化時會增加 revision，即使底層收到 duplicate/no-op command。因此不能只見 revision 增加就演成功入貨／陳列。
對 buy／display，至少核對 captured command id 在 before 未存在而在 after 新加入，並驗證相應命令結果。
入貨量採用該已接受命令的真實 quantity；不可用 inventory 淨增加，因同一 commit 可能先 settle 賣貨再 buy。
對 display，確認捕捉的 targetSlot 確實由原內容改成該接受結果；無變更不演成功換陳列。
同一 commit 有 soldUnits 及 accepted-command effect 時，兩者都要給真實回應，視覺動作可作有界短序列。
現有 core 沒提供逐筆買家／購物籃資料；紙袋保持 generic，售出件數不等於客人／交易筆數。

L5. 生命週期與重播保障
valid committed receipt 的去重消耗先於 hidden／stale epoch 的視覺略過。即使當時不播，也不能回到頁面後重播。
取消一次動作與重設存檔 baseline 是不同操作；hidden／普通 repaint 不清空已消耗 revision。
同一 mode／shop stream 使用正確 baseline；import／restore 導致資料來源更換或 revision 可能回退時，建立新的 stream incarnation／epoch 並切斷舊 callback。
建立 NativeServiceSequencer 時明確傳入當前 app-wide presentationEpoch：new NativeServiceSequencer(streamKey, loaded.revision, presentationEpoch)。切換模式亦保持這個取消計數器單調增加，不能重設成 0。save incarnation 只在存檔身份真正更換時更新，不因每次 hide／resume 而重造。
不能把一個未驗證或其他 stream 的 receipt 當作合法新 revision，導致吞掉之後真事件。
模組對數值／型別的檢查不會證明 caller 的 persistence 成功；成功邊界仍由現有儲存 adapter 負責。
UI 的已提交結果由 authoritative snapshot 顯示；視覺 pending queue 合併／略過不得令資料消失。

L6. 場景應用及清理
現有 v9 world.ts 的 frame delta 是 milliseconds；隨附模組的 tick／advanceVisibleTime／sampleIdle 使用 seconds。接駁時明確將 dtMs / 1000 轉換一次，不能直接傳原有毫秒值，也不能重覆轉換。距離維持 metres，角度維持 radians。
可見時間取樣及 delta 限制要與現有 frame loop 一致，hidden 返回不追趕 elapsed time 或補播行路／交易。
模組輸出的姿勢需混合到角色 rest pose；不可將中立 0 直接當作所有模型骨架的正確局部角度。
轉換角度／座標系、身高、步幅及 pivot 時記錄約定。不要將距離驅動步態描述成已實作完整 foot IK。
只有角色在合理位置且可到達時安排接袋；否則讓 Misaki 做包裝／收據回應，不能瞬移客人到櫃檯。
取消序列時同步清理臨時袋／箱／表情／服務站點 reservation；新 sequence 不受舊 callback 影響。
