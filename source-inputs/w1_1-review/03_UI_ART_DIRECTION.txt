下一站・小店物語 — W1.1 介面及美術規格
這是實作方向；不修改 Bible 的世界觀、正式人物、品質階級或經濟批准範圍。

1. 視覺目標
一間讓人想停留的日本生活選物小店：暖木、奶油色、柔紫、植物、安靜光影與清晰商品。
保留真正 3D 微縮世界。這次對話的 CSS 互動示意只說明構圖、顏色和操作；正式版本繼續使用可互動 3D scene。

以固體可讀面板為主，半透明／模糊只用在少量 chrome。low quality 可移除 blur，不影響資訊。
卡片圓角約 12–18px；主面板 20–24px；極淡陰影。主要按鈕明顯，次要操作較輕；避免每個按鈕都用高飽和色。
沿用已持有原檔與授權的語言字體；標題具層次、內文 14–16px 起、次要文字通常不低於 12px、財務數字 tabular-nums。使用五語實際字串驗證。
主要可點擊區至少約 44×44 CSS px；長文換行，不用省略號藏關鍵錯誤、金額、目標貨架。

3. 主畫面
Top：玩家 mark＋店名，次行池袋／生活選物店；現金為唯一主要數字。
Status：真實營業狀態、東京時間、正常／沙盒標記；時間估算限制放適當說明。
World：待機時目標 70–80% 畫面；貨架選中時柔紫框線／底座高亮；對應面板顯示相同架號。
Next step：一張簡短卡，只顯示當下最有用的動作。完成便更新／收起。
Nav：店務、入貨、結算／手記等短標籤配一致圖示；設定、語言、Zen 在容易找到的更多入口。現有功能不可因精簡而消失。
操作細節按需打開，關閉後回到店舖；可完整使用 keyboard。

4. Desktop / narrow viewport
桌面：側欄約 320–380px，按實際可用區域調整鏡頭 target，避免店舖被遮。
窄屏：底部面板或可收合區；頂部不塞三個 KPI；主導航有足夠 touch area。按面板高度重算 scene 可視區，safe-area 留白。
320、375、430、768 與桌面寬度分別檢查五語；長英文／泰文／日文不得令末項離開畫面。
開鍵盤時仍能看到輸入、錯誤與套用；只有可捲動內容區捲動，避免整個店舖跟輸入跳。

5. 商品卡與陳列
卡片有可辨識 thumbnail／簡化 3D preview，不再只是一個色點。
顯示名稱、庫存、入貨單價、數量 stepper、入貨總額、入貨後現金。
主按鈕例：「入貨 5 件 · ¥500」；次按鈕例：「上架至陳列架 2」。不足顯示差多少，沒有庫存時上架操作說明原因。
購買成功：一次輕微數字變化＋「鉛筆 ×5 已入貨」，不跳離目前商品／丟失 scroll。
上架成功：對應架物件更新，目標保持一致，說明替換物仍留庫存。
定價：目前價、草稿價、參考價、清楚套用／取消。不得聲稱未經模型支持的保證收入。

6. 結算
先顯示選定期間、售出件數與淨盈利；收入、已售商品成本、人工、租金、營運費按序展開。
小提示：「未售商品仍是存貨，售出後才計入商品成本。」
當期損益、目前現金／庫存、累計採購分清期間。歷史日報不可混入最新 modifier breakdown。
所有數值由 core state 讀取；不要用示意數值實作真遊戲。

7. 成交、缺貨、樣本
成交：由 committed sale delta 觸發輕量通知／短音效／貨架數量變化；同一結果只播一次，支援一次結算多筆。
缺貨：在對應架顯示補貨入口；不連續彈出阻擋。
樣本揭示：簡短、可跳過的聚焦演出，物件、名稱、Select quality 與獨立 Unique tag；維持零數值教學樣本。揭示後明確完成，reload 不重發。
所有裝飾 NPC 仍是表現；不和經濟交易一對一硬綁。
動作建議 150–220ms 作起點；respect prefers-reduced-motion。音訊只在玩家啟用後播放，細節不蓋過閱讀。

8. 3D 美術第一輪範圍
先做店舖主視覺：floor／wall 材質、window light、接觸陰影、櫃檯／架 bevel 與腿、收銀機、price tag holder、小植物。
優先 notebook／pencil／mug／tote 等可辨識形體，沿用 stable Offering IDs 和 manifest。
一般角色改善 silhouette 與色彩即可；正式角色與寵物按 Bible 後續製作。
不要在 W1.1 新增完整天氣、晝夜、雨夜故事或 premium collection。燈光提升是現有靜態場景的品質工作。

9. 資產與平台
保存 authoring source、GLB masters、原始貼圖／音訊／字體、生成 recipe、licence／來源與 SHA256。
Web optimization 產生獨立衍生檔。能共享材質意圖與幾何，不代表 Babylon shader 或 CSS 可直接用於 URP。
新資產記清單：來源、用途、所屬 ID、尺寸／軸／pivot、材質／rig／clip、衍生方式、Web 驗證、native 待測。
無 WebGL 的 review 不能代替材質／動畫／影子實測；不得標為 Unity／iOS／Android 已相容。
