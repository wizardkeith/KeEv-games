【A. 必須修復的問題】

A1. 調價需求餘額
原重現：notebook 1 件、價格 81 units、開店 10 分鐘累積 demandRemainder 592560；改為 100000 units，至第165分鐘可售一件，從開始維持高價則0件。
本 gate 採明確簡單規則：實際價格改變時重設該 Offering 的 fractional demand remainder；完全同價的 no-op 保留。所有入口走 core，不能只在 UI 防堵。
更新 contract、simulation version／舊存檔遷移處理；加 low→high／high→low／no-op／interval split／reload regression。不得因修補改變 unrelated accounting。

A2. 負現金且零存貨的復業死路
原重現：正常新店保持關店11日，cash=-280 units，stock=0，最便宜買貨也拒絕。
實作最小免費復業支援，作為清楚標示 provisional 的 W1.1 規則；不要等待玩家重開、付費或刪存檔。
最低要求：
  • 根據目前 cash、可售庫存及最低復業需要判斷資格，不能把一般正常店都變成無條件領錢。
  • UI 預覽支援效果及下一個可行入貨／上架動作；領取後能在該測試情境重新經營。
  • 支援和既有歷史損益分開記錄；不是 sales／net-profit unlock progress，不倒改過往 rent／P&L。
  • 在 atomic core command 內重新判斷資格後寫入，commandId dedup；reload、重複點擊與多分頁不重複領同一操作。亦要測不同 command IDs 同時申領，不能只依賴同 ID 去重。
  • 支援金額、可重用條件及持續扣租風險寫成具體可測試的資料規則，放 docs/RECOVERY_W1_1.md，標明不是正式 balance 批准。
  • 不只 clamp 畫面為0，也不默默刪債／刪 ledger；維持 cash reconciliation，可追溯 support amount。
可先用最小、有限範圍的復業補助方案；不要為此實作完整銀行／貸款／商城。請自行選擇符合上述限制的具體暫定規則，完成 code、UI、schema migration 和情境測試後交付。

A3. 嚴格 numeric validation
每個數字欄位都先 type-check number、safe integer、欄位範圍；禁止 coercion。
至少覆蓋 cash、timestamps、revision／eventSequence、tutorial、inventory stock／price／bookCost／remainder、reports、expense remainders，以及新增 recovery fields。
原案例 stock="10" 匯入後 buy1 變"101"。修後應拒絕匯入，原良好存檔保持完整。測試 strings／null／boolean／arrays／unsafe integers、invalid references，保留有效 migration path。

A4. command ledger 邊界
有效存檔有100000 command IDs 時，settle 仍可按 watermark 結算，因為不新增 ledger entry。
維持一般新增指令的上限、重複 ID no-op 和 CAS，不偷偷 prune IDs。

A5. 錯誤與自動結算
cash／quantity／price 等 nonblocking form error 不能令自動／focus／visibility settlement 停止。顯示具體原因與修正方法。
save-stale、clock rollback、long_gap、storage failure 使用各自正確處理；不要把全部 errorCode 當成同一全域暫停。時間趕上後可恢復；長間隔按既有分段原子 catch-up；存檔衝突不能覆蓋新 revision。

A6. 草稿與目標貨架
分離 UI draft state 與 simulation state。自動結算後保留未提交售價、數量、店名／公司名、焦點、選取位置及 scroll；套用才 commit。
所有貨架入口（世界點選、空架入貨、selector、商品卡）共享同一選中 slot；上架按鈕顯示具體架號。修正「架2入貨仍操作架1」。替換已有貨架顯示清楚回饋，原商品保持在庫存。
避免連按重複購買：pending 時立即正確鎖定相關動作，UI intent ID／core dedup 配合；不以 queue 無限新增購買處理雙擊。

A7. 教學、模式與時段
教學條件用實際 state predicates。若提示 notebook＋pencil，就檢查兩者；若允許自由選，文案相符。不能任何一次 buy／display 就跳到下一步。條件達成後記錄 milestone，後來成交耗掉庫存或重新陳列不令已完成教學倒退。

「營業中」以東京營業時段及 open 設定共同判定；非營業時間可做店務，不能畫成正常成交中的狀態。
揭樣本後有清楚完成卡及下一個可選行動，不永久重覆教學文字。

A8. 報告期間
