# W1 simulation and persistence contract

The sole active simulation is TypeScript and requires a later Unity/C# port or replacement. Presentation and platform adapters call engine-neutral commands and versioned records; Babylon objects never own balances. Authoritative state is entirely independent of render frames, quality, displayed crowd, tab visibility and device speed. Browser timers only request settlement to an explicit target; a resumed tab settles elapsed time rather than replaying render frames.

Numbers are JSON integers, validated as safe integers. Monetary/state magnitudes are bounded to 10^12 normalized units; timestamps to 2100-01-01 UTC (4,102,444,800,000 ms). Arithmetic intermediates used for cost allocation must pass Number.isSafeInteger or the command is rejected atomically. There is no lossy int64-to-JavaScript conversion. Display is a fixed 10 JPY per normalized unit, no live FX. Percentages use integer basis points; monetary division uses half-even. Demand and expenses carry fractional remainders explicitly.

The ordered stages are base demand → neutral local context → neutral Offering modifiers → neutral staff → neutral equipment → test set modifier → neutral event → per-item allocated capacity → price-adjusted conversion (0–100%) → sales → goods consumed → salary/rent/operations → net profit → neutral pending ratings. The report preserves ordered stage values; economic stages refer to the latest Tokyo-date report. Set effects sum as a stacking group then cap at +3000 bp. Supplier discount is capped at 2000 bp. There are no general net-profit percentage modifiers. All non-neutral balance values are provisional fixtures, not researched Ikebukuro economics.

Current demand is six unit opportunities/hour per display, total capacity eighteen/hour distributed equally across assigned displays (including empty ones). The desk test set adds 1000 bp to demand; the capacity ceiling still applies. Suggested/actual price determines integer conversion, capped at 100%; an increased price reduces conversion. Low price never allows conversion to exceed served capacity. Physical NPCs only suggest activity and are not individual economic transactions.

Stock purchase pays cash and increases inventory book cost. Perpetual moving weighted-average cost uses exact integer book-cost allocation with half-even for partial sales; the last sale consumes all remaining book cost. No cost is recognized twice. Wages 30/hour and operations 10/hour accrue during trading hours while open. Rent 20/hour accrues all the time; cash may become negative without game over. No eviction, staff departure or login penalty is implemented. W1.1 includes provisional free reopening support; see RECOVERY_W1_1.md.

Settlement completes absolute UTC minute boundaries, reports by Tokyo UTC+9 date and uses explicit open/close hours. The first partial minute is part of its absolute minute bucket; commands before a minute completes affect that minute. This quantization is a provisional prototype rule, not final timing/balance approval. The watermark records exact target milliseconds; remainders carry across intervals. One hour, two half-hours, many small foreground updates and one background/resume interval produce equal economic state under identical commands. Midnight/day changes are chronological. Sandbox is a separate namespace, manual clock and fixed initial 2026-10-21 Tokyo 10:00; normal clock is wall-time based. Both modes are untrusted and rankingEligible=false.

IndexedDB read/write transactions read current revision, reject a stale tab, compute commands on a clone, and write the complete economic state plus watermark in one record. Transaction abort/interruption leaves the old full record intact. Regular commands have persistent IDs for deduplication (100,000 command limit; no silent pruning); settlement is idempotent by watermark and does not grow the command ledger. Repeated imports are explicit user-directed replacement and are not authoritative account/anti-cheat operations. Backdating imports is allowed only as untrusted prototype data; future rankings cannot consume them.

Clock rollback rejects mutation; the UI pauses automatic settlement until time catches up. A gap over 31 days returns long_gap without advancing/discarding the interval. An explicit catch-up-one-day control processes each day in a separate atomic transaction. This is a technical work bound, not a reward cap. The clock/data bounds, oversized imports (>8 MB), bad references, malformed JSON, invalid schema/content/simulation versions and unsafe numbers reject without replacement. Corrupt stored data is retained, with a raw export recovery action. Schema v2 is current; strictly validated v1 migrates as specified in MIGRATION_W1_1.md. Schema v0 and unknown versions are explicitly rejected. Browser eviction/private browsing can still remove local saves; users can export backups. Trusted time, online CAS/cloud accounts, shared-world authority and leaderboards remain pending.

Identity, shop/district/layout IDs, staff roster, shelf Offering IDs, book costs, prices, reports, tutorial/reveal flags, command IDs, deterministic sale sequence, versions, time and fractional remainder state survive save/reload. No ambient randomness exists in this W1 loop. The discovery sample is a deterministic tutorial flag with Select quality, a separate Unique tag and no stats. All six tiers exist in content; no Masterpiece drops exist.


## W1.1 amendments

Simulation ts-w1-2 clears an Offering's fractional demand only on an actual price change; same-price no-op retains it. New tutorial progress follows a free-choice route using stocked inventory, stocked display, open setting, first committed sale and reveal predicates. Once reached, milestones do not regress when goods sell out or displays change. Migrated earned W1 progress is retained.

Free reopening support is separately recorded financing and is never sales/profit/unlock credit. Strict numeric type/range validation covers every snapshot and grant field. See MIGRATION_W1_1.md and RECOVERY_W1_1.md for exact compatibility and provisional policy.
